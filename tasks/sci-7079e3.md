The reproduced mm30 corpus pins a successor contract (mm30:4af7c421...) that compiles only from the chain cut 22 -> cut 31 -> current, each document the next one's predecessor. science's launcher loader parses every contract document as a genesis (predecessor None) and catches only MalformedContract, so a successor document reaches the person as internal-error and the mm30 corpus cannot be mounted. A contracts or read_contracts entry becomes a path (genesis, as today) or a table { document, predecessors = [oldest, ...] }; the loader walks the chain oldest first, catches SuccessionViolation and MalformedContract and refuses naming the entry. Tests: a chain compiles to the successor's identity; a bare path still parses a genesis; a mismatched predecessor refuses by name; a successor given bare refuses by name; a table missing a key refuses by name. Framework design 9.1 takes a dated amendment and the README's configuration paragraph names the shape. Design: docs/specs/2026-10-26-second-project-milestone-design.md section 4.2 and 5.3 (sci-0d00d2), whose criterion 1 this unblocks.

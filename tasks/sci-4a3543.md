Commons 1a acceptance (science/acceptance.py counts, branch 3) checks that the named origin's marker selection lists the address, but record ids are kind:local slugs and a marker's selection lists ids only, so a carrier can hold different content under an accepted origin's address and still count. In 1a, world reads refuse one address in two corpora (Deviation 3), so this reaches only corpus-local reads with origin and carrier both configured. Milestone 1b (beliefs-81367e) lifts that limit and needs a per-address content identity on Carrier compared against the origin's. Ruled deferred in the 1a SDD ledger (Task 10, I2b).

Scope evidence at science 846772e: Carrier, _origin_holds and counts still carry no per-address content identity; python/tests/test_acceptance.py exercises address selection and pin/attribution gates without an equal-address content-substitution case. [ref:brief] records the current local-read exposure, the unchanged requirement to land with sci-9104fb's overlap support, and the existing design owner.

Wait on beliefs-918fd2, which already decides content identity, equal/different-content holders, acceptance's holder set and publication attribution. Reuse that output rather than defining a competing equality contract here. After the design, scope a Carrier/predicate change with matching-content acceptance and equal-address/different-content rejection cases; preserve origin-confirmed pin, accepted-world, exact-marker and first-origin checks. Do not make this depend on completing sci-9104fb: that milestone requires this fix with overlap. Its world-overlap implementation still depends on beliefs-81367e. The existing corpus-local gap remains until the content check lands.

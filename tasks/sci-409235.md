`beliefs.holdings.boundary.write` appends a holdings write intent to the observer corpus before the store write. When the store then refuses, no observation follows, and the holdings reducer (rules_v1 `_unsettled`) blocks that location as `unsettled`. It stays blocked until a later `re-check` intent at the same location is matched. Beliefs provides `recheck`, but no science command reaches it, so the block can only be cleared by writing around science.

Wanted: a science command (or an existing command's path) that re-checks a store location under the holdings permit and publishes the observed outcome (Absent here), settling the intent.

Instance: in the mm30 world, the working corpus holds chain entry 553be3ce71bdd8b48b17f534f335126be69d73a32950e1aab4ad64ecb17aef7d (event token 956c6da01fa221f94336d7dab1294e53) for location store:05b6c1225e710bb1559f36e8333f3f29:2061b3731c13ccf956499f10015d9312472edabafc0554b001bb35c0f8f44955/mask-key.json, left by invocation 6cf80d367660d05be56a00f686e7f23c (2026-10-30, mm-62e2da). Settling it is a world write and needs the user's authorization. The store is read-only-serviceable, but a re-check only reads it.

Design how projects are manifested in verifiably: a project is a view (beliefs UA §4.2), a corpus is the provenance boundary, a workspace is a git repository of code and runs. Settles when a user creates a directory, how the current project is selected per session (never from cwd), how code and data attach to the world, how export levels map to views and destinations, and how biology/health/cancer relate (biology is the domain contract, health and cancer are project views, containment is emergent). Names the second-project milestone (health viewing mm30 facts) as the first multi-project dogfood. Precursor to sub-project 4.
